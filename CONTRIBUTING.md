# Contributing to OpenSpot

OpenSpot welcomes corrections, new payload adapters, reproduction reports, documentation, and validation data.

## Before opening a change

- Open an issue for changes that alter a mechanical interface, electrical design, protocol, supported component, or safety-related behavior.
- State what was tested, on which hardware/software revision, and what remains untested.
- Do not present simulations, bench checks, or a single field run as general safety or reliability evidence.
- Do not commit credentials, robot serial numbers, private network details, proprietary Boston Dynamics material, or third-party assets without redistribution permission.

## Hardware contributions

Include native editable source, a neutral exchange format, revision information, material/process assumptions, and enough assembly context for review. Changes to a released interface should document compatibility and measurements.

By contributing hardware design material, you agree that it may be distributed under CERN-OHL-W-2.0. Original documentation contributions are distributed under CC BY 4.0 unless a file states otherwise.

## Review checklist

- Links and filenames resolve on a case-sensitive filesystem.
- Available, experimental, and planned features are distinguished.
- Images have useful alt text and reasonable file sizes.
- Third-party products and trademarks are attributed without implying endorsement.
- Validation steps are repeatable and include failure or limitation notes.
